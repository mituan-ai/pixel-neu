# art-inbox/AGENTS.md：参考资料与美术草稿的交付约束

这里是参考资料和美术草稿的收件箱。草稿要经过审核，选中的再由维护者接进 `tools/` 和 `assets/`。
根目录 AGENTS.md 的真实性、比例与方向、署名与许可条款在这里同样适用。

## 可以写的位置

| 位置 | 放什么 | 进仓库 |
|---|---|---|
| `art-inbox/` | 草稿、候选素材、联系表、校验脚本 | 只有本文件进仓库 |
| `data/ref/<区域>/` | 照片、视频截图、网页截图、卫星图裁切 | 不进仓库 |
| `docs/refs/<区域>.md` | 参考资料的文字索引：链接、日期、朝向、能确认什么、量得的尺寸、待核实 | 进仓库 |

其他目录一律不改，包括 `tools/`、`assets/`、`src/`、`server/`、`shared/`、`data/survey.json`、`docs/sources.md`。
`npm run sat`、`npm run check` 可以跑，它们只往 `data/` 写本地参考图。

区域名：`gate` 北门，`info` 信息学馆，`plaza` 十字广场与校训石，`library` 图书馆、南广场与鼎，`sides` 两侧楼群，`common` 通用设施（路灯、长椅、车棚、标牌等）。

## 密钥

API 密钥都在仓库根目录的 `.env.local` 里，比如天地图的 `TIANDITU_TK`。需要用时从环境变量读取。
不得把密钥写进任何文件、日志、截图或提交，也不得在输出里打印。

## 参考资料

- 每条资料在 `docs/refs/<区域>.md` 里占一行，编号写成 `R-<区域>-NN`，表格列为：
  - 编号
  - 链接
  - 发布方或作者
  - 拍摄或发布日期
  - 相机朝向（地理方位，比如「向南看北立面」）
  - 能确认什么
  - 本地文件名

  正式编号（S 号）由维护者登记进 `docs/sources.md`。
- 本地文件命名为 `data/ref/<区域>/<编号>-<内容>.<扩展名>`。视频只截关键帧，并记下视频链接和时间点。
- 优先找这些来源：
  - 学校和学院新闻、活动报道（常能看到台阶、入口、雕塑）
  - 校园导览、新生指南、校园平面图
  - B 站、抖音等平台的校园漫步视频和航拍视频
  - 校友照片、百度百科、Wikimedia Commons
- 资料要写明说了什么、没说什么。凭照片估出的尺寸，要写出估法，比如「以门高约 2.2 m 为参照数台阶」。拿不准的写进该文件末尾的「待核实」。
- 楼名、层数、年代这类事实至少要两个独立来源。只有一个来源时，标「单一来源」。

## 美术草稿

### 尺度与视角

- 比例：1 m = 8 px；一层 30 px；地面一格 16 px = 2 m。人物见下文。
- 视角：3/4 俯视。地面和屋顶按正投影画，立面按真实高度竖直画在占地上方，没有透视、没有斜角。
- 「视角」指屏幕上方朝向哪个地理方向。默认上北视角下看到的是物体的南立面。地标和不对称的物件要分别画 N、E、S、W 四个视角，带文字的面不能用镜像代替。

### 光影与描边

- 光源固定在屏幕左上：受光面在左和上，背光面在右和下。
- 投影朝右下，统一用 `shadow`（`#1d2a3a`），透明度约 60/255。
- 物件外轮廓用 1 px 的 `ink`（`#2a2433`）描边；建筑立面不描外轮廓。

### 色板

- 只用 `assets/palette.gpl` 里的颜色。
- 确实需要新颜色时，在该素材的 json 的 `newColors` 里写出色值和理由，由维护者决定是否加进色板。

### 文件格式

- PNG、RGBA、整像素。不要抗锯齿，不要半透明（投影除外），不要放大预览当成品。
- 每张图配一个同名 `.json`，字段如下：

  | 字段 | 含义 |
  |---|---|
  | `w`、`h` | 图的像素宽高 |
  | `ax`、`ay` | 脚底锚点：物件底边中点在图中的位置 |
  | `footprint_m` | 占地宽和深，单位米 |
  | `height_m` | 高度，单位米 |
  | `view` | 视角 N、E、S 或 W，立面图写朝向 |
  | `refs` | 依据的 R 编号列表 |
  | `confidence` | `据资料`、`部分推断` 或 `中性占位` |
  | `notes` | 补充说明 |

### 立面图

- 建筑草稿交正立面图：正投影的平面图纸，宽度等于真实立面长度乘 8 px，标出层线、门、窗、台阶、雨棚、塔楼退台。
- 另交一张屋顶平面图。生成器会把立面和屋顶挤出成 3/4 视图，所以不要自己画 3/4 楼体。
- 没有资料的立面不画，在 `index.md` 里写「缺资料」。

### 人物

- 人物用 Q 版 24×32 规格：一帧 24×32，脚底在第 30 行，3 帧（迈步、站立、迈步）× 4 个朝向（下、左、右、上），游戏里按 1 倍显示。细节见 `art/chibi/README.md`。
- 新发型优先找 OpenGameArt 上给 Cabbit 24×32 底模做的 CC0 素材，连同作者、链接一起交。
- 自己画的部件要和 `art/chibi/base-male.png` 的头对齐（同一帧、同一位置），按原色画，染色由生成器做。

### AI 生成图

AI 生成的图片只能放在 `art-inbox/concept/`，当作构图参考，不能当成品，也不能被描摹成品直接交付。

## 第三方素材

- 只收 CC0、CC-BY、OGA-BY、CC-BY-SA 授权的素材。CC-BY-SA 素材要连同完整的作者署名链一起收。
- 原样放进 `art-inbox/third-party/<素材包>/`，同目录写 `SOURCE.md`，内容包括：
  - 链接
  - 作者
  - 许可证及许可证链接
  - 下载日期
  - 用到了哪些文件
  - 打算怎么改：缩放、改色、重绘
- 改过的版本放在 `art-inbox/third-party/<素材包>/adapted/`，注明「改自哪个文件」。

## 交付与审核

- `art-inbox/index.md` 是总清单，每项一行，列为：
  - 文件
  - 区域
  - 类别
  - 依据（R 编号）
  - 状态：草稿、待审或有疑问
  - 问题
- 每批交付附一张联系表 `art-inbox/sheet-<批次>.png`：素材按 1 倍和 2 倍并排，放在草地和铺装两种底色上，旁边放一个 24 px 高的人物剪影作比例参照。
- 可以在 `art-inbox/tools/` 写校验脚本，检查色板、尺寸和 json 是否齐全。交付前跑一遍。
- 不要提交 git，只在上面表里的三个位置写文件。不确定的地方记进 `index.md` 的「问题」，然后继续做下一项，不要停下来等回复。
