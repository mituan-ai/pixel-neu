# assets/AGENTS.md：美术规范

这里的文件会原样发布到网站根目录（本文件除外，打包时会被剔除）。目前所有图片都由 `tools/art*.ts` 程序生成。规范的目标是：以后换成手绘时风格不跑偏，新旧素材能放在一起用。

## 视角与比例

- **3/4 俯视**：地面正投影，建筑和物件的南立面（朝屏幕下方的一面）竖着画出来，立面高度直接叠在占地上方。
- **方向**：屏幕上方是地理上的**南**（地图整体旋转了 180°，再加 3.85° 的校园轴线校正）。这样北门在下方，进门就能看到信息学馆朝北的正立面。画任何"朝向"相关的细节前，先想清楚它在屏幕上朝哪边。
- **比例**：1 格 = 16 px = 2 m。全图统一，不压缩距离。
- **建筑层高**：一层 18 px。勒脚 4 px，女儿墙 3 px，右侧投影 6 px。常量在 `tools/tiles.ts` 的 `BUILDING`。
- **角色**：一帧 16×24 px，脚底中心是锚点。4 个方向（下、左、右、上）× 3 帧（站、左脚、右脚）。

## 光照与轮廓

- 光从**左上**来。阴影落在右侧和下方，统一用 `shadow` 色半透明叠加，不要另调阴影色。
- 角色、物件外轮廓用 `ink` 色 1 px 描边。地面瓦片和建筑立面不描边。
- 禁止抗锯齿、模糊、渐变。透明只用 0 或 255，阴影叠加是唯一的例外。

## 调色板

- **唯一调色板**：`tools/palette.ts` 的 `PAL`。生成器会导出 `palette.gpl`（Aseprite、GIMP 可直接载入）和 `palette.png`。
- 手绘也只用这些颜色。确实缺颜色时，先在 `PAL` 里加，再重新生成，保证程序素材和手绘素材共用同一套色。
- 角色的皮肤、头发、衣服是**灰度图 + 运行时染色**：`avatar.png` 里这几层用 `tint0`–`tint3` 四级灰度画，颜色在 `shared/social.ts` 的选项数组里。新增衣服颜色只改数组，不重画图。

## 文件与布局

| 文件 | 内容 | 布局 |
|---|---|---|
| `tiles.png` | 地面瓦片 | 16 列，每格 16×16。序号含义见 `tools/tiles.ts` 的 `TILESET` / `GROUND` |
| `props.png` + `props.json` | 物件图集（树、路灯、长椅、校门柱、纪念物） | `props.json` 记录每个物件的矩形和锚点 `ax, ay`（脚底） |
| `avatar.png` | 角色分层 | 每层 4 行（方向）× 3 列（帧），层从上到下依次为 skin、bottom、top、detail、hair（hair 有 5 种发型）。行号见 `shared/social.ts` 的 `AVATAR` |
| `emotes.png` | 表情 | 一行，每帧 18×18，顺序同 `EMOTES` |
| `buildings/b<OSM id>.png` | 每栋楼一张 | 宽度等于占地宽，高度等于占地加立面。左上角对齐占地左上角再往上偏移 `top` |
| `map.json` | Tiled 格式地图 | 生成产物，不要手改 |
| `fonts/` | Fusion Pixel 12px 简中子集与 OFL 许可证 | |

## 换成手绘的流程

1. 用 `palette.gpl` 在 Aseprite 等工具里画，尺寸和锚点与原文件完全一致。
2. 覆盖 `assets/` 里的同名文件。
3. 把文件名加进 `tools/art.ts` 的 `HANDMADE` 集合，之后跑 `npm run art` 就不会覆盖它。
4. 跑 `npm run art`，在 `data/preview.png` 和浏览器里检查与周围素材是否协调。

## 真实性

- 建筑轮廓来自 OSM 占地。层数、立面特征（窗带、塔楼、柱廊）要有照片依据，依据记在 `docs/sources.md`。
- 没核实过外观的东西（目前是「大书」「能量球」两座雕塑）用中性占位：底座加简单形体，不要凭想象画细节。核实后再替换，同时更新 `docs/design.md` 的待核实表。
- 不画校徽，不画学校的官方标识。校门柱上的校名牌只画成示意的竖排笔画。
