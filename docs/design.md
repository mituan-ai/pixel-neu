# 设计说明

记录地图怎么从真实资料变成游戏画面、哪些地方做了取舍，以及还没核实的内容。改地图或美术之前先读这一篇。

## 首个区域：北门 → 信息学馆 → 宁恩承图书馆

南湖校区的中轴线。从北门进校，经过三角地草坪和校训石，到信息学馆北广场，穿过信息学馆两翼之间的院落，再到大书广场和宁恩承图书馆。两侧各带一部分楼群和道路作为边界。

| 路线 | 游戏内步行距离 | 步行时间 |
|---|---|---|
| 北门 → 信息学馆 | 约 172 m | 约 17 秒 |
| 信息学馆 → 图书馆 | 约 204 m | 约 20 秒 |
| 北门 → 图书馆 | 约 346 m | 约 35 秒 |

（按游戏寻路实测，步速 80 px/s，约等于 10 m/s。距离是真实比例，只是走得快。）

## 坐标与投影

1. **经纬度 → 米**：以 (41.7655, 123.4135) 为原点做局部平面近似，x 向东，y 向南。
2. **转正 3.85°**：南湖校区的路网整体有偏转，由信息学馆北墙（OSM way 87664797，3.84°）和图书馆北墙（3.92°）量得。转正后主要楼和路都能对齐格子。
3. **整体旋转 180°**：屏幕上方是地理上的南。
4. **比例**：1 格 = 2 m = 16 px，全图统一，不压缩距离、不挪动建筑。
5. **范围**：东西各到两侧楼群中部，北到北门外约 30 m，南到汉卿北路以南的鼎。地图 136×244 格。

### 为什么旋转 180°

信息学馆的正立面（阶梯式塔楼、正门）朝北，正对北门。3/4 俯视只能画出朝屏幕下方的那一面。如果按"上北下南"摆放，信息学馆最有辨识度的一面就会朝着屏幕上方，玩家看不到。旋转 180° 之后，北门在屏幕下方，进校门往上走就能正面看到信息学馆，和真实的入校体验一致。

代价是宁恩承图书馆的正门朝南，现在朝向屏幕上方，看不到。游戏里看到的是图书馆的北立面（朝向大书广场和信息学馆的一面）。

## 资料怎么用

- **OSM**（`data/osm.json`）：校园边界、道路、步道、建筑占地、水体、纪念物和雕塑的点位。这些是硬约束，生成器照搬，不手动改位置。
- **照片和平面图**：只用来确认 OSM 没有的信息，例如楼层数、立面特征、校门形制、校训石旁的花坛。照片不进仓库。
- **DESIGN 补充**：OSM 没画、但画面需要的东西。每一项都在 `tools/map.ts` 里标了 `DESIGN` 并写明依据：

| 补充项 | 依据或理由 |
|---|---|
| 主干道两侧 3 m 人行道和行道树 | 校园照片中主干道两侧都有铺装人行道 |
| 三角地草坪、信息学馆前庭和中轴铺装 | 取自 OSM 顶点围合的范围，铺装纹理是视觉处理 |
| 院落里的半圆形草坪 | 卫星图上院落中央有绿地。形状做了简化 |
| 前庭和三角地两侧的针叶树 | 北门、校训石方向的照片 |
| 校训石底座两侧的红花 | 校训石照片 |
| 路灯、长椅 | 不改变布局的停留点。人会在这些地方停下来碰面 |
| 广场每 8 格一道深色铺装带、草地深浅斑块 | 纯视觉，避免大面积单调 |

## 建筑

- 占地来自 OSM 的建筑多边形，按格子栅格化。
- **高度**：一层画 18 px。信息学馆两翼 5 层、中段 7 层、塔楼 10 层，塔顶加亭子和旗杆，按北门方向的照片目测。图书馆和其他楼按 4 层画。
- **立面**：信息学馆中段画竖向窗带，入口在中轴上。图书馆画密排的竖向壁柱。其他楼用通用立面。
- **遮挡**：建筑按列切片，每片的深度取这一列占地最靠前的一排，所以 U 形楼的院子里，人会正确地站在后楼前面、前楼后面。玩家被楼挡住时，会在楼上方叠一层半透明的自己。
- 碰撞只按占地算，屋顶和立面不挡路。

## 交互

- 键盘方向键或 WASD 行走，点击或触摸地面会自动寻路走过去（按格子做广度优先搜索，再拉直路线）。正面顶到障碍物时，角色会自动往空的一侧挪一点绕过去。
- 1–6 发表情，T 打开预设短语，M 开关小地图，Esc 关闭菜单。
- 头顶从下往上依次是名字、表情、短语。人挤在一起时，靠后的人整摞往上让开，互不遮挡。名字只显示附近最近的 12 个人。
- 走近地点会弹出介绍卡片，卡片底部列出资料来源。

## 扩展指南

**新增一片区域**

1. 在 `tools/osm.ts` 调整抓取范围，`npm run osm`。
2. 在 `tools/map.ts` 调整地图范围，给有名字的楼登记到 `NAMED`，需要特殊立面的写一个 style。
3. 地点介绍写进 POI 列表，每条带来源编号。新来源先登记到 `docs/sources.md`。
4. `npm run map && npm run art && npm test`，检查 `data/preview.png`，再到浏览器里走一遍。

**新增外观选项**：在 `shared/social.ts` 对应数组末尾追加颜色。新发型需要在 `tools/art-avatar.ts` 画一层，并更新 `AVATAR` 的行数。

**新增表情或短语**：只能追加到数组末尾（序号就是网络协议），表情图同步加到 `tools/art.ts`。

**换手绘素材**：见 `assets/AGENTS.md`。

## 验收标准

首个区域做完后，用下面五条判断美术方向是否成立、能否扩展到全校：

1. **辨认测试**：给五到十位没看过项目的东大师生看一张无文字截图，多数人能说出这是哪里，并指出至少一栋地标。这一条最重要。
2. **路线测试**：让测试者口头描述一条熟悉的路线，再在游戏里走一遍，看地标的顺序和方位是否和描述一致。
3. **拥挤测试**：同屏十到二十个角色时，人物、名字、建筑依然清楚，聚集点不堵。
4. **统一测试**：灰度检查通过；随便挑一个素材，旁人看不出是后加的。
5. **生产效率**：能按 `assets/AGENTS.md` 在可预期的时间内做出一栋新的通用建筑，质量与现有的一致。

当前进度：第 3 条已用 30 个模拟客户端在信息学馆前测过，第 4 条程序素材全部来自同一调色板。第 1、2、5 条需要真人参与。
