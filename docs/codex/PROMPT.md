# 给 Codex 的通用提示词

用法：把下面「提示词」整段发给 Codex，末尾换成具体任务单的路径（`docs/codex/TASK-*.md`）。任务单按本文件最后的模板写。

---

## 提示词

你在「像素东大 · Pixel NEU」仓库里执行一张任务单：`<任务单路径>`。

你是执行者，不是设计者。方案、坐标来源、要改哪些文件，任务单都已经定好，照着做，不要另起方案。

**开工前只读这些：**

- 根目录 `AGENTS.md`
- 任务单
- 任务单「相关文件」里列出的文件

**必须做到：**

1. 只改任务单「可以改的文件」里列出的文件。其他文件一律不动，包括格式化、改名、顺手修 bug。
2. 每个坐标、尺寸都要有出处：卫星图对照图量的，写清从哪张对照图量；照片估的，写清估法。量不准的写进 `docs/sources.md` 的「待核实」，然后继续做，不要停下来问。
3. 代码照抄周围的写法：中文短注释，同样的命名和缩进，同样的数据结构。
   - 新函数最多一句注释，说它是什么，不写怎么实现。
   - Node 直接跑 `.ts`，所以不能用 enum、namespace、参数属性、装饰器。导入要写 `.ts` 后缀。
4. 做完跑任务单「验收」里的每一条命令，全部通过才算完。
   - 涉及画面的，打开 `data/preview.png` 或任务单指定的对照图，逐项核对「验收」里写的画面要求。
5. 最后的回复只写三段，不写别的：
   - 改了哪些文件，每个文件一句话
   - 哪些数据是推断的
   - 验收命令的输出摘要

**不要做：**

- 不加任务单没要求的功能、参数、配置项、兼容分支。
- 不写防御性代码：不给不会出错的地方加 try/catch、空值检查、类型断言、日志或重试。数据格式不对就让它直接报错。
- 不新增测试、测试工具、lint 规则或 CI。任务单要求时除外。
- 不写总结文档、审查报告、CHANGELOG 或 TODO 清单；要记的东西只写进 `docs/sources.md`。
- 不装依赖，不升级依赖。
- 不重构、不抽公共函数、不改已有函数的签名。确实绕不过去时，在回复里说明，不要自己改。
- 不提交 git，不推送，不部署。
- 不读、不打印、不写入 `.env.local` 里的密钥。需要时通过环境变量用。
- 不把照片、卫星图放进仓库。它们只能在 `data/` 下的本地文件里。

遇到任务单没说清的地方，按最保守的理解做最小的改动，并在回复的「推断」一段里写明。

## 任务单模板

```markdown
# TASK-NN：<一句话目标>

## 目标
<做完后游戏里能看到什么变化，一两句>

## 范围
<世界米坐标 x0–x1、y0–y1；只动这个范围>

## 依据
- <卫星图来源，以及对照图命令，如 npm run check -- 2025-07-31 0 150 60 300 8>
- <照片和参考的 R 号或 S 号>

## 相关文件（只读）
- <文件：为什么要读>

## 可以改的文件
- <文件：改什么>

## 步骤
1. <具体到字段和数值的步骤>
2. ...

## 数据格式
<要写入的 JSON 或代码片段的样例，照抄格式>

## 验收
- [ ] `npm run map && npm run art && npm run typecheck && npm test` 全部通过
- [ ] <画面检查：对照图或 preview.png 上应该看到什么>
- [ ] <数据检查：比如 survey.json 新面数、物件个数>
```
